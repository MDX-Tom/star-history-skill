# Deploy Star History Pages

Replace a fragile hosted Star History image URL with static light and dark SVGs generated by the official Star History renderer inside GitHub Actions and served from the repository's own GitHub Pages site.

## Workflow

### 1. Inspect the target repository

1. Read the nearest `AGENTS.md`, the main README, any translated README, and existing Pages workflows.
2. Run `git remote get-url origin` and derive the target as `owner/repository`.
3. Check whether `.github/scripts/render_star_history.py` or `.github/workflows/sync-star-history.yml` already exists. Preserve intentional local customizations.
4. Determine the Pages origin:
   - Project site: `https://owner.github.io/repository`
   - User or organization site named `owner.github.io`: `https://owner.github.io`

### 2. Install the reusable files

Run the bundled installer from this skill directory:

```bash
python3 scripts/install.py \
  --root /path/to/target-repository \
  --repository owner/repository
```

The installer writes:

- `.github/scripts/render_star_history.py`
- `.github/workflows/sync-star-history.yml`

It refuses to replace different existing files unless `--force` is supplied. Use `--dry-run` before overwriting an existing setup. Optional flags include `--pages-url`, `--source-ref`, and `--cron`. Keep the installer's tested upstream commit SHA by default; use `--source-ref main` only when following upstream tip is an intentional choice.

### 3. Update project documentation

Use the HTML `<picture>` snippet printed by the installer. Add or replace the README's Star History block in every maintained language version.

Requirements:

- Load `star-history-dark.svg` for dark color schemes.
- Load `star-history-light.svg` for light color schemes and the `<img>` fallback.
- Point image URLs at the repository's Pages origin, not `api.star-history.com`.
- Keep the chart link pointed at the interactive Star History website if desired.
- Preserve existing README style, heading depth, alignment, and translation parity.

### 4. Configure GitHub

The workflow expects a repository secret named `STAR_HISTORY_GITHUB_TOKEN`.

1. Create a fine-grained personal access token scoped only to the target repository with read-only metadata access. A classic token limited to public-data access is also suitable for a public repository.
2. Add it as the `STAR_HISTORY_GITHUB_TOKEN` Actions secret.
3. Set **Settings → Pages → Build and deployment → Source** to **GitHub Actions**.

Never put the token in a workflow literal, README, committed `.env` file, artifact, or command output. The workflow masks the secret, removes upstream token-fragment logging, writes the value to a mode-restricted runner temporary file, and deletes the file during cleanup.

Read [references/operations.md](references/operations.md) before changing token handling, enabling Pages through `gh`, pinning the upstream renderer, or diagnosing a failed run.

### 5. Validate locally

Run:

```bash
SKILL_DIR=/absolute/path/to/deploy-star-history-pages

python3 -m py_compile .github/scripts/render_star_history.py

python3 "$SKILL_DIR/scripts/install.py" \
  --root . \
  --repository owner/repository \
  --dry-run
```

If `actionlint` is installed, also run:

```bash
actionlint .github/workflows/sync-star-history.yml
```

Review `git diff --check` and verify that neither generated file contains unreplaced `__PLACEHOLDER__` values.

### 6. Deploy and verify

When remote deployment is part of the user's request and GitHub CLI is authenticated:

```bash
gh workflow run sync-star-history.yml --repo owner/repository
gh run watch --repo owner/repository --exit-status
curl -fsS https://owner.github.io/repository/star-history-light.svg >/dev/null
curl -fsS https://owner.github.io/repository/star-history-dark.svg >/dev/null
```

For the first deployment, allow GitHub Pages a short propagation delay. Confirm both SVGs render in the README and switch correctly with the viewer's color scheme.

## Implementation invariants

- Run the official `star-history/star-history` backend only on `127.0.0.1` inside the Actions runner.
- Fetch star data through GitHub's API with the repository secret; do not call the hosted Star History chart API.
- Validate downloaded content as SVG before publishing it.
- Produce both light and dark files atomically.
- Deploy only when either generated SVG differs from the current Pages copy.
- Keep `contents: read`, `pages: write`, and `id-token: write` as the workflow's minimal job permissions.
- Use a concurrency group with cancellation so scheduled and manual runs do not race.
- Keep the static Pages copy available between runs, including periods when the hosted Star History service is unavailable.
- Prefer a reviewed commit SHA for the third-party renderer because the workflow executes that code while a read-only GitHub token is present.
- Patch upstream diagnostic messages so backend failures never reveal token prefixes or suffixes in Actions logs.

## Completion report

Report:

1. Target repository and Pages URL.
2. Files created or changed.
3. Local validation commands and results.
4. Whether the secret and Pages source still need user-side configuration.
5. Whether the workflow was triggered and the two public SVG URLs were verified.
